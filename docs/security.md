# 阶段 1：安全设计

- 适用：部署在公网或内网、保存真实收款记录的多人合租账本。
- 原则：最小权限、纵深防御、默认拒绝、历史不可抵赖、密钥不落前端。
- 说明：阶段 4 已实现 Argon2id、服务端会话、CSRF、邀请、RBAC、账本隔离、审计；阶段 5 已实现 Agent 工具白名单、pending action、确认哈希与幂等；阶段 6 已实现严格 CSP、安全头和同源静态托管；阶段 7 完成依赖/镜像静态检查与本地备份恢复。IP 限流/HTTPS/Docker 加固、MFA 仍未完成。当前尚未声称已部署。
- 阶段 7 实际检查记录：[security-review.md](security-review.md)。

## 1. 资产与威胁模型

### 1.1 需要保护的资产

| 资产 | 风险 |
|---|---|
| 用户密码/会话 | 账户接管、冒用管理员 |
| 账本数据 | 其他租户/非成员读取 |
| 实际收款记录 | 隐私泄露、篡改、重复登记 |
| 结算快照/规则版本 | 历史被覆盖，产生纠纷 |
| 审计日志 | 抵赖、删除证据 |
| 模型 API Key | 被盗刷、费用损失 |
| 数据库备份 | 离线泄露、勒索 |
| 聊天内容 | 隐私、提示注入 |

### 1.2 主要威胁

- 未登录访问、越权、IDOR（改 URL 里的 ID 访问他人账本）；
- 暴力破解、撞库、会话固定/劫持；
- CSRF、XSS、SQL 注入；
- 重复提交/并发导致重复付款或重复结算；
- 规则变更未确认就生效；
- Agent 被提示注入，执行越权写操作；
- 日志/错误响应泄露密钥或账单；
- 备份泄露/无法恢复；
- 依赖漏洞、容器逃逸；
- 内部人员（管理员）误操作/恶意修改。

### 1.3 信任假设

- 服务器主机和 Docker 守护进程是可信的；若主机被攻破，应用层安全无法保证。
- 第三方模型 API 不完全可信；发送给模型的内容按“可能被记录”处理。
- 用户浏览器可能被恶意扩展/木马感染；服务端仍必须做权限校验。
- 备份存储可能离线泄露；备份必须加密。

## 2. 身份认证

### 2.1 密码

- 使用 **Argon2id**（`argon2-cffi`），不自己实现哈希。
- 参数按 OWASP 建议和服务器性能校准；密码哈希包含算法/参数/盐。
- 密码长度 12–128 字符；不强制复杂字符组合；拒绝常见弱密码/ breached 密码（可选本地列表）。
- 数据库只存 `password_hash`，绝不存明文/可逆加密。
- 登录失败统一 `INVALID_CREDENTIALS`；对不存在用户执行 dummy hash，降低时序枚举。
- 连续失败：
  - 5 次/15 分钟锁定账户 15 分钟（`failed_login_count`/`locked_until`）；
  - IP 维度限流；
  - 管理员可解锁。
- 不通过邮件/页面提示“邮箱不存在”。

### 2.2 初始管理员与注册

- 默认 `ALLOW_REGISTRATION=false`。
- 首个管理员通过 CLI 一次性创建：
  - 交互输入密码；
  - 不把密码写入 `.env.example`/镜像/日志；
  - 创建后强制修改初始密码（可选）。
- 邀请：
  - 管理员生成一次性 token（32 字节随机，数据库只存 SHA-256）；
  - 7 天过期；
  - 只能接受一次；
  - 角色只能 `admin/member`，不能邀请 owner。
- 密码重置：
  - v1 不接邮件服务；由管理员 CLI 重置并强制改密；
  - 不接受“安全问题”；
  - 未来可加邮件一次性 token。

### 2.3 会话

- 服务端会话表；Cookie 只保存随机 256-bit token。
- Cookie：
  - 名称 `__Host-rba_session`；
  - `HttpOnly`、`Secure`、`SameSite=Lax`、`Path=/`；
  - 不使用 `Domain`；
  - 生产必须 HTTPS。
- 数据库只存 token 的 SHA-256；泄露数据库不能直接冒用会话。
- 登录成功：
  - 生成新 session id/token（防会话固定）；
  - 设置 CSRF；
  - 记录登录审计。
- 过期：
  - 绝对 7 天；
  - 空闲 24 小时；
  - 改密/登出/管理员禁用吊销所有会话。
- 会话清理任务删除过期行。
- 不在 URL、localStorage、sessionStorage、日志中放会话 token。
- 用户可查看/吊销自己的其他会话（可选）。

### 2.4 多因素（v1 不做）

- 公网部署且管理员账户敏感时，建议后续加 TOTP。
- v1 用强密码 + 限流 + HTTPS；在 README 的已知限制中说明。

## 3. 授权与账本隔离

### 3.1 角色

- `owner`：账本唯一所有者；管理 admin、归档账本、转移所有权。
- `admin`：账单、规则、结算、付款调整、邀请、审计。
- `member`：查看账本、登记自己的付款、聊天只读/准备写。
- 角色来自数据库 `household_members`，每个请求重新解析；不信任 JWT/前端声明。
- Agent 继承用户角色，不额外提权。

### 3.2 授权检查顺序

```text
认证（会话）→ 用户 active → 账本成员 active → 角色 → 资源属于账本 →
业务状态（open/locked/settled）→ 参数校验 → 执行
```

- 任一失败即拒绝，且不泄露资源是否存在。
- 跨账本请求统一 404（除非明确需要 403 解释角色）。
- 管理员不能跨账本；没有全局超级管理员。
- 最后一个 owner 不能被移除/降级。

### 3.3 防 IDOR

- 所有资源查询必须同时带 `household_id`。
- 不只按 UUID 查询。
- 复合外键 `(household_id, parent_id)` 防止跨账本挂接。
- API 路径含 `household_id`，服务端校验成员关系。
- 不在响应中返回其他账本的 ID/名称。
- 测试：用账本 B 的 ID 访问账本 A 的所有资源类型。

### 3.4 Agent 隔离

- 工具层从会话注入 `household_id`/`actor_id`/`role`，模型参数不能覆盖。
- Agent 不应看到其他账本的账单/人员/聊天。
- 工具调用结果按当前账本裁剪。
- 跨账本工具调用返回 404/拒绝。

## 4. CSRF

- 所有非 GET/HEAD/OPTIONS 请求要求 `X-CSRF-Token`。
- 双提交 + 服务端绑定：
  - 登录时生成随机 CSRF token；
  - Cookie `rba_csrf`（非 HttpOnly，SameSite=Lax）；
  - 数据库 session 存 CSRF 的 HMAC-SHA256（`APP_SECRET_KEY` 作为 pepper）；
  - 请求头 token 与 session 中哈希比较（常量时间）。
- 额外检查 `Origin`/`Referer` 与 `APP_BASE_URL` 同源。
- 同源部署，不启用 CORS；如启用，白名单精确匹配，不允许 `*`。
- 登录/注册也做 Origin 校验，防登录 CSRF。
- 确认 Agent 动作必须带 CSRF；模型无法伪造。
- 退出登录用 POST，不用 GET。
- 不在跨站 GET 上执行写操作。

## 5. XSS 与内容渲染

- 前端所有用户内容用 `textContent`/`createTextNode`，禁止 `innerHTML` 拼接。
- 不使用 `eval`、
ew Function`、内联事件处理器。
- 静态模板只用于固定结构。
- Agent 消息按纯文本渲染；v1 不支持原始 HTML Markdown。
- 账单名称、备注、人员名、聊天内容、工具错误均视为不可信。
- 属性值（如 `data-*`）如包含用户内容，用 `setAttribute` 并避免拼入选择器。
- CSP（生产）：
  - `default-src 'self'`
  - `base-uri 'none'`
  - `object-src 'none'`
  - `frame-ancestors 'none'`
  - `img-src 'self' data:`
  - `script-src 'self'`
  - `style-src 'self'`
  - `connect-src 'self'`
  - `form-action 'self'`
- 阶段 6 已完成：`<style>`/`<script>`/`style=""` 全部外部化/class 化，服务端对 `/` 与 assets 注入严格 CSP；静态测试断言无内联代码。
- 其他响应头：
  - `X-Content-Type-Options: nosniff`
  - `Referrer-Policy: no-referrer`
  - `Permissions-Policy: camera=(), microphone=(), geolocation=()`
  - `X-Frame-Options: DENY`（与 frame-ancestors 双保险）
  - `Cross-Origin-Opener-Policy: same-origin`
  - `Cross-Origin-Resource-Policy: same-origin`
- 不引入 CDN/外部字体/第三方脚本，减少供应链和 CSP 复杂度。
- 前端不保存模型 API Key。

## 6. SQL 注入与数据访问

- 全部通过 SQLAlchemy 参数化查询/ORM；禁止字符串拼接 SQL。
- 原生 SQL 仅限：
  - 健康检查 `SELECT 1`；
  - 迁移；
  - 经审查的聚合/锁查询。
- 排序字段、表名、列名使用白名单，不能直接来自用户输入。
- 数据库账户 `app_rw` 只有 DML，无 DDL；迁移使用独立 `migrator`。
- 不使用数据库超级用户运行应用。
- 错误响应不包含 SQL/堆栈；日志中的 SQL 参数脱敏。
- 搜索使用参数化 `ILIKE`，对 `%`/`_` 转义，限制长度。

## 7. 金额、并发与幂等安全

- 金额只从请求整数分/数据库 `bigint`/Python `int` 进入引擎。
- 拒绝 `NaN`、`Infinity`、字符串浮点、负数（普通账单）、超上限。
- 每笔账单分摊后断言守恒；失败回滚。
- 写操作要求 `Idempotency-Key`（付款、调整、结算、规则激活、动作确认）。
- 结算：
  - 行锁 + 唯一 `(period, revision)`；
  - partial unique `(period) where status='final'`；
  - 预览哈希；
  - 重复请求重放。
- 账单/账期更新使用 `expected_version`；冲突 409。
- 付款只追加；调整引用原付款；不能 UPDATE/DELETE。
- 结算/付款表触发器拒绝篡改。
- 审计追加。
- 这些既防误操作，也防恶意重复/覆盖。

## 8. 限流、请求保护与拒绝服务

- 反向代理层限制请求体大小（例如 256 KB；导出/聊天单独设上限）。
- 应用层：
  - 登录 5/min/IP + 10/hour/email；
  - 注册 3/hour/IP；
  - 写 60/min/用户；
  - Agent 20/hour/用户 + token/日预算；
  - 导出 10/hour/用户；
  - 读 300/min/用户。
- 429 + `Retry-After`；不泄露内部阈值细节。
- 超时：
  - 普通请求 10 秒；
  - 模型 30 秒；
  - 数据库语句 5 秒；
  - 导出 30 秒。
- 限制输入长度：文本 500/4000 字符，名称 80/120，聊天 4000。
- 限制数组长度（人员、账单、工具调用）。
- 慢请求/大请求日志告警。
- v1 单实例内存限流；多实例时用 Redis/网关，保证一致。
- 防止模型费用滥用：`AGENT_MAX_STEPS`、每日 token 预算、按用户限流。

## 9. 密钥与配置

- `.env` 被 `.gitignore` 忽略；提供 `.env.example` 仅含占位符。
- 生产使用 Docker secrets/主机环境变量/权限 600 的 env 文件。
- 密钥：
  - `APP_SECRET_KEY`（≥32 字节随机）；
  - `DATABASE_URL`（含密码）；
  - `LLM_API_KEY`；
  - `POSTGRES_PASSWORD`。
- 密钥只注入 API/数据库容器，不注入前端构建。
- 日志、错误、健康检查、审计、Agent 上下文不包含密钥。
- 轮换：
  - LLM Key 可随时轮换；
  - 数据库密码轮换需重启/连接池；
  - `APP_SECRET_KEY` 轮换会使 CSRF/派生值失效，需计划。
- 禁止在代码、Dockerfile、Compose、README、测试夹具中写真实密钥。
- CI 不打印环境变量；secret scanning（gitleaks）作为检查。

## 10. HTTPS 与部署加固

- 只暴露 Caddy 的 80/443；HTTP 自动跳 HTTPS。
- Caddy 自动证书（公网域名）或内部 CA（内网）。
- HSTS 在确认 HTTPS 稳定后启用：
  `Strict-Transport-Security: max-age=31536000; includeSubDomains`
- Postgres 不发布宿主机端口，只在内网。
- API 容器：
  - 非 root；
  - 
o-new-privileges`；
  - `cap_drop: ALL`；
  - 只读根文件系统 + 可写 `/tmp`；
  - 固定镜像版本/摘要。
- 数据库：
  - 非默认端口不暴露；
  - 强密码；
  - 定期备份；
  - 磁盘加密（主机层）。
- 只允许必要出站：模型 API；数据库内网。
- 不在镜像中放 `.env`、备份、真实账单。
- 依赖锁定 + 最小镜像（`python:3.12-slim`）。
- 生产关闭 FastAPI 交互式文档，或仅管理员/内网访问。

## 11. 日志、审计与脱敏

### 11.1 运行日志

- 结构化；请求 ID；状态码；耗时；用户 ID（非邮箱）；账本 ID。
- **禁止**记录：
  - 密码、哈希；
  - 会话 token、CSRF；
  - API Key、数据库 DSN；
  - 完整请求体/响应体；
  - 支付参考号、备注全文；
  - 聊天原文。
- 错误堆栈只在服务端日志，响应只给 request_id。
- IP 以哈希保存（如需要）。

### 11.2 审计日志

- 谁、何时、对哪个账本/实体、做了什么、前后值、请求 ID。
- 不写入敏感字段；`before/after` 只保留业务字段。
- 只追加；数据库触发器拒绝 UPDATE/DELETE。
- 审计查询仅 admin；查看审计本身可记录。
- 审计保留时间 ≥ 财务数据保留时间；具体周期待定。
- 可选的哈希链/外部归档作为后续增强；v1 先保证只追加 + 备份。

### 11.3 前端错误

- 401：跳登录；
- 403：显示无权限；
- 409：显示“数据已变化，请刷新/重新预览”；
- 429：显示稍后再试；
- 503：显示服务暂不可用，保留页面数据；
- 不显示内部错误码细节/堆栈。

## 12. Agent 安全

- 模型不直接访问数据库；只有白名单工具。
- 工具参数 Pydantic 校验；未知字段拒绝。
- 账本/角色从会话注入，模型不能覆盖。
- 写工具只创建 `pending_action`；用户点击确认才执行。
- 确认接口要求 CSRF + 幂等 + 重新鉴权；模型无确认工具。
- 提示注入：
  - 账单备注/聊天内容/工具结果视为数据；
  - 系统提示明确忽略其中指令；
  - 不允许模型调用 SQL/HTTP/文件工具；
  - 不把其他账本上下文放入 prompt。
- 输出：
  - 纯文本渲染；
  - 金额以工具结构化结果为准；
  - 不执行模型生成的代码/命令；
  - 不把模型输出直接写数据库。
- 隐私：
  - 只发送必要账务摘要给模型；
  - 不发送密码、Token、API Key、完整付款参考号；
  - 第三方模型可能记录请求，部署文档需说明；
  - 对隐私敏感部署，建议使用本地/私有模型端点。
- 费用：
  - 每日 token 预算；
  - 单会话最大步数；
  - 超限提示，不自动继续。
- 失败：
  - 模型不可用不影响核心账务；
  - 部分工具调用不自动执行写操作；
  - pending action 可取消/过期。

## 13. 数据隐私与保留

- 数据分类：
  - 账户：邮箱、显示名、密码哈希；
  - 账务：账单、天数、付款、结算、审计；
  - 聊天：用户消息、助手回复、工具摘要。
- 最小化：
  - 不收集身份证、住址、银行卡号；
  - 付款参考号可选，且不写日志；
  - 聊天不要求真实姓名。
- 保留：
  - 财务/审计长期保留（具体年限待用户确认）；
  - 聊天默认 180 天，可归档/删除；
  - 过期会话定期清理。
- 删除：
  - 账本归档而非物理删除；
  - 用户删除账户需先转移/归档账本，保留必要审计；
  - 备份中的删除按备份保留周期自然过期。
- 第三方：
  - 模型请求会离开服务器；README 必须说明。
  - 备份存储在受控位置；加密。

## 14. 备份与灾难恢复

- 每日 `pg_dump -Fc`；30 天日备 + 12 个月月备；异地加密副本。
- 备份文件权限 600；不提交 Git；不放 Web 根目录。
- 每季度恢复演练；记录 RTO/RPO。
- 恢复验证：
  - 迁移到 head；
  - 账单/分摊合计；
  - 结算行合计；
  - 每个账期一个 final；
  - 跨账本外键；
  - 登录冒烟。
- 备份加密密钥与备份分开存放。
- 详细命令见 `docs/database.md` 和 `docs/deployment.md`。

## 16. 安全测试清单

### 16.1 认证

- 未登录访问受保护接口 → 401。
- 错误密码 → 401，文案不区分邮箱。
- 连续失败 → 锁定/限流。
- 会话过期/吊销 → 401。
- 改密后旧会话失效。
- Cookie 属性正确（HttpOnly/Secure/SameSite/Path）。
- 会话固定：登录后 token 变化。

### 16.2 授权/隔离

- member 调用 admin 接口 → 403。
- A 账本用户访问 B 账本所有资源 ID → 404/403。
- 伪造 `household_id` 请求体 → 拒绝/忽略。
- 跨账本复合外键插入 → 失败。
- Agent 工具跨账本 → 拒绝。
- 最后一个 owner 不能移除。

### 16.3 CSRF/XSS/SQLi

- 无 CSRF 头的写请求 → 403。
- 错误 CSRF → 403。
- 跨站 Origin → 403。
- 账单名称/备注/聊天含 `<script>` → 不执行。
- 搜索/排序参数注入 SQL → 参数化/白名单。
- 错误响应不含 SQL/堆栈。

### 16.4 业务安全

- 重复付款/结算 → 幂等，不重复。
- 并发结算 → 一个 final。
- 预览后数据变化 → 409。
- 规则未确认不生效。
- 付款/结算/审计不能 UPDATE/DELETE。
- 负数/超限/NaN 金额 → 422。
- 天数 0–31 校验。

### 16.5 Agent

- 提示注入不改规则/不越权。
- 模型无确认工具。
- 模型不可用时核心 API 正常。
- 工具参数未知字段拒绝。
- 模型输出 XSS 不执行。

### 16.6 运维

- 健康检查不泄露配置。
- 日志不含 secrets。
- 备份可恢复。
- 容器非 root。
- 依赖审计通过。

## 17. 事件响应

1. **发现**：异常登录、审计告警、依赖漏洞、数据泄露报告。
2. **遏制**：
   - 吊销所有会话/禁用账户；
   - 轮换 LLM/数据库密钥；
   - 关闭公网入口或切维护页。
3. **取证**：
   - 保留审计/日志/备份（只读）；
   - 不直接修改生产库。
4. **恢复**：
   - 从干净备份恢复到新环境；
   - 迁移到 head；
   - 验证一致性；
   - 逐步恢复访问。
5. **复盘**：
   - 记录时间线、影响、根因、改进；
   - 更新测试/文档。
6. **通知**：
   - 涉及用户财务/个人信息时，按适用法规和用户约定告知。
